# Бизнес-правила

Правила ниже — это наименьшие устойчивые решения, подтверждённые кодом и тестами. Указанные
тесты — это доказательства; отсутствие рантайма вживую молча не превращается в «пройдено».

| ID | Правило | Доказательство |
|---|---|---|
| BR-AUTH-001 | Запрос не должен раскрывать записи другого рабочего пространства. | Тесты владения/авторизации в `tests/test_mail_integrity.py` |
| BR-MAIL-001 | Предпроверка доставляемости и предпросмотр не обращаются к провайдеру. | Тесты предпроверки в `tests/test_mail_deliverability.py` |
| BR-MAIL-002 | Одной и той же компании не отправляется несколько групповых исходящих сообщений за одну операцию. | Тесты группового исходящего в `tests/test_supplier_identity.py` |
| BR-MAIL-003 | Использованный получатель не переиспользуется молча; альтернативный вариант должен быть `NEVER_USED` перед выбором. | Тесты альтернативного получателя в `tests/test_mail_status_semantics.py` |
| BR-MAIL-004 | Повтор идемпотентной операции не создаёт ещё одно сообщение или задачу. | Тесты идемпотентности в `tests/test_mail_integrity.py` |
| BR-MAIL-005 | `accepted` и `delivery_unknown` не являются автоматическим разрешением на повтор. | Тесты повтора в `tests/test_mail_status_semantics.py` |
| BR-MAIL-006 | Жёсткий отказ доставки подавляет будущее использование; мягкий отказ сохраняет восстанавливаемое состояние и историю. | `tests/test_mail_status_semantics.py`, `mail/bounce.py` |
| BR-MAIL-007 | Дозирование, резервирование, бюджет и kill-switch проверяются в момент отправки. | `tests/test_mail_pacing.py`, `tests/test_mail_deliverability.py` |
| BR-MAIL-008 | Пауза/стоп рассылки и переходы между стадиями устойчивы и соблюдаются очередью задач. | `tests/test_mail_deliverability.py` |
| BR-MAIL-009 | Сбои провайдера классифицируются; таймаут после принятия провайдером — это неопределённость, а не безопасный повтор. | `mail/deliverability.py`, `tests/test_mail_status_semantics.py` |
| BR-MSG-001 | Входящие сообщения дедуплицируются и остаются видимыми при отсутствии совпадения с заявкой. | `tests/test_mail_integration.py`, `tests/test_messages_visibility.py` |
| BR-SUPPLIER-001 | Один ИНН группируется в одну идентичность; разные значения ИНН остаются раздельными. | `tests/test_supplier_identity.py` |
| BR-DATA-001 | Разрушительное удаление заявки заблокировано, пока разрешение доставки не завершено. | `tests/test_mail_status_semantics.py` |
| BR-RUNTIME-001 | Только канонический рантайм может владеть канонической блокировкой; остальные рантаймы пишут только в свой манифест. | `tests/test_canonical_runtime.py`, `mail/runtime.py` |
| BR-CONTENT-001 | HTML санитизируется, а загрузка внешних изображений не является обязательным условием для отображения. | `mail/content.py`, `tests/test_mail_deliverability.py` |

## Интерпретация безопасности

Эти правила не авторизуют реальные отправки на продакшене, применение миграций, изменение
учётных данных, удаление клиентов, развёртывание, force-push или merge.
