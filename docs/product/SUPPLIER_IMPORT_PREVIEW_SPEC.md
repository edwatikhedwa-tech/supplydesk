# Импорт поставщиков: безопасный preview-контракт

## Цель

Импорт не записывает строки в SupplyDesk сразу после выбора файла. Первый
релиз принимает CSV и создаёт временный preview: пользователь видит, какие
столбцы распознаны, что будет создано и какие строки требуют решения. Запись
доступна только следующим явным действием подтверждения и создаёт лишь новые
карточки поставщиков.
Excel, Google Sheets, CRM/ERP и 1С остаются будущими адаптерами того же
контракта, а не отдельными путями записи.

## Границы первого релиза

- Поддерживается CSV UTF-8 или UTF-8 with BOM, разделитель автоматически
  определяется между запятой, `;` и tab; лимит — 1 МБ и 500 непустых строк.
- Допустимые целевые поля preview: `name`, `inn`, `site`, `email`, `phone`,
  `region`, `role`, `note`. Неизвестный столбец можно пропустить; он не
  попадает в БД. В текущем CSV Apply сохраняются только поля карточки
  `name`, `inn`, `site`, `email`, `phone`, `note`; `region` и `role` видны в
  preview и прямо названы не сохраняемыми, пока для них не появится точная
  сущность и UX.
- Mapping предлагается по заголовку, но всегда доступен для ручной правки.
- Нормализация не выдумывает значения: ИНН валидируется существующей
  функцией, email/телефон очищаются только безопасно, исходная строка
  сохраняется в preview для сравнения.
- Дубликат определяется только по точному ИНН внутри текущего workspace и не
  сливается автоматически. Строка с совпадением всегда пропускается; название
  и другие поля существующей карточки не обновляются.
- Реальный Apply требует отдельную кнопку подтверждения с итогом: сколько
  новых строк будет создано, сколько пропущено как дубликаты и сколько требуют
  исправления. До этого шага нет `INSERT`/`UPDATE` поставщиков, контактов,
  заявок или `canonical_companies`.

## Безопасность и видимость

- Импортируемые контакты — workspace data, не canonical/public data.
- Нет автоматического обогащения, внешнего поиска, Checko/DaData-запроса,
  отправки письма или публикации контакта при preview/import.
- Каждая созданная карточка получает время создания, а в `audit_events`
  сохраняются `source=import`, строка CSV и автор операции. Это provenance
  импорта, не подмена данных внешним реестром.
- Ошибочная строка не должна блокировать разбор остальных, но блокирует Apply
  этой строки, пока пользователь не исправит mapping/значение.

## Критерии приёмки CSV-first

1. CSV с кириллицей и `;` создаёт preview без записи в рабочие таблицы.
2. Пользователь меняет mapping и видит пересчёт preview.
3. Пустой/некорректный ИНН, пустое имя и дубликат по ИНН показаны отдельно,
   без авто-merge.
4. Preview отменяется без остатка; Apply требует чекбокс и отдельное явное
   подтверждение, создаёт только новые карточки и не делает `UPDATE`.
5. Два workspace не видят preview/данные друг друга.
6. Тесты подтверждают CSV, неясные поля, дубликаты и отмену; browser
   проверяет desktop/mobile без горизонтального overflow.

## Текущий срез реализации

- `POST /api/supplier-import/preview` принимает `csv_text` и optional mapping
  в авторизованной сессии. Он создаёт response-preview и apply-plan в памяти,
  но не выполняет записи в БД.
- `POST /api/supplier-import/apply` требует `confirmed: true`, заново строит
  plan по текущему workspace и выполняет только `INSERT ... ON CONFLICT DO
  NOTHING`: существующая карточка не может быть обновлена даже при гонке после
  preview.
- Экран «Поставщики» показывает итог и отдельный checkbox подтверждения перед
  записью, а после Apply сообщает созданные и пропущенные строки.
- XLSX, Google Sheets, CRM/ERP/1С и ручной merge остаются отдельными
  адаптерами/действиями следующего этапа.
