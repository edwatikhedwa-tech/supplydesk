# Пользовательские сценарии

Пошаговые описания, проверенные по реальному коду (а не по внешнему виду интерфейса, принятому за
работающую функцию). Техническое описание на уровне функций —
[`../technical/DATA_FLOW.md`](../technical/DATA_FLOW.md).

## 1. Авторизация

Пользователь попадает на `/login` → выбирает email+пароль или «Войти через Яндекс» (кнопки
Google/Mail.ru честно неактивны, подписаны «Скоро» — это не скрытая заглушка) → ставится cookie
сессии → при каждой загрузке страницы заново проверяется `/api/auth/me`; истёкшая сессия
возвращает на экран входа с понятным сообщением. **Подтверждено как реальное**, модель с одним
заранее заведённым владельцем-аккаунтом (не общая регистрация).

## 2. Заявки

Покупатель нажимает «Новая заявка», заполняет название/описание/позиции → заявка создаётся со
статусом `draft` (черновик) → запускает поиск → статус меняется на `searching` (идёт поиск),
прогресс-бар продвигается по мере того, как устойчивая очередь задач обрабатывает результаты SERP
и обогащение в фоне (переживает перезагрузку страницы или холодный старт serverless посреди
поиска) → статус становится `completed` (либо `error` с понятной причиной, например, если не
настроены учётные данные XMLRiver). Покупатель может фильтровать/сортировать таблицу
поставщиков, пометить поставщика как нерелевантного, добавить домен в чёрный список или указать
ИНН вручную.

**Сейчас недоступно в этом сценарии:** отслеживание или приостановка уже запущенной *массовой
рассылки* — вся эта возможность (страница `CampaignPage.tsx` в старом фронтенде) не имеет
аналога в v2 (`GAP-001`). Покупатель, запустивший массовую рассылку сегодня, не может поставить
её на паузу или остановить из рабочего интерфейса.

## 3. Поставщики

Поиск → обогащение → контакты → привязка к заявке, по подробной модели в
[`SUPPLIERS.md`](SUPPLIERS.md). С точки зрения пользователя: поставщик, найденный через поиск по
одной заявке, становится видимым и переиспользуемым в других заявках того же рабочего
пространства (карточка `global_suppliers`), с прикреплёнными данными реестра/финансов после их
получения. **Известный подтверждённый живой недочёт:** если позже поставщик отвечает с личного
адреса (Gmail/Яндекс/Mail.ru), отличного от домена компании, который нашёл поиск, система может
создать *вторую*, дублирующую карточку поставщика, которая и будет держать реальную переписку —
данные обогащения при этом «застревают» на исходной, не связанной с перепиской карточке.
Затрагивает примерно каждого 9-го поставщика в проверенной локальной базе. См.
`GAP-003`/`INV-SUP-002`.

## 4. Сообщения

Покупатель открывает «Сообщения», видит переписки, сгруппированные по заявкам, плюс «Письма без
заявки» — для всего, что система не смогла привязать автоматически. Открытие переписки помечает
её прочитанной. Ответ, пересылка ссылки, просмотр встроенных изображений — всё отображается через
санитизированный (очищенный) HTML-конвейер (внедрить произвольный script/style невозможно).
Переписку можно пометить как `in_progress`/`deferred`/`rejected` (личная рабочая метка, никогда
не влияет на отправку/чёрный список). Переписка без ответа дольше срока SLA показывает
`needs_followup` («требует внимания»), предлагая «Связаться» (зафиксировать результат звонка)
или «Напомнить» (создать задачу). **Ни одно письмо и ни одна переписка никогда физически не
удаляются** никаким действием пользователя — меняется только статус/видимость.

## 5. AI-ассистент

Из открытой переписки кнопка «Открыть ИИ-помощника» позволяет покупателю задать вопрос;
ассистент отвечает, используя историю сообщений этой переписки, по желанию дополненную другими
поставщиками этой же заявки, которые *уже ответили* — это подсказка на уровне интерфейса, а
настоящая граница безопасности — перепроверка на сервере каждого id переписки против рабочего
пространства и заявки, а не этот клиентский фильтр. По умолчанию ограничен 10₽ расходов в день;
дальнейшие вопросы честно отклоняются с сообщением «лимит достигнут», а не молча проваливаются.

## 6. Задачи / Календарь

Покупатель создаёт задачу (по желанию привязанную к заявке/поставщику), указывает дату/время и
канал напоминания. **Что реально происходит в момент наступления срока:** если вкладка открыта —
появляется тост и (если разрешено) системное уведомление, опрос идёт каждые 45 секунд. Если
выбран канал «Email» или «Телефон» — ничего не отправляется: у email вообще нет пути отправки, а
телефонный вариант прямо в тексте интерфейса помечен как заглушка. На дашборде отображается
реальный виджет календаря с точками на днях, где есть задачи; клик по задаче/дню открывает
детали. Отдельной полноэкранной страницы календаря больше нет (удалена 17.09.2026 как
недостижимый мёртвый код после того, как пункт меню на неё уже был убран ранее).

## 7. Расчёт стоимости доставки

Для пары «заявка + поставщик» покупатель может запросить разовую оценку стоимости доставки через
Dellin. Небольшая, самодостаточная функция, проверена вживую на реальном API Dellin — не
заглушка.
