# Единый backlog MVP SupplyDesk

Этот backlog переводит требования владельца в проверяемые независимые задачи.
`DONE` разрешён только после фактической проверки; `PARTIAL` здесь не
используется как финальный статус и раскрывается в описании. Реализация и
текущий оперативный факт — в [`ai/CURRENT_STATE.md`](../../ai/CURRENT_STATE.md).
Подробный UX-контракт — в [Approved MVP Interface](APPROVED_MVP_INTERFACE.md).

## Очерёдность

P0 не блокируется phone reminders. После P0 последовательно уточняются P1:
формат денег, заметки, общие заголовки, Dashboard, таблицы и карточка
поставщика. P2 развивает рабочий контекст задач, календарь, напоминания,
контакты, импорт, классификацию и безопасную связку личной/корпоративной
почты небольшими отдельными изменениями. P3 не
должен вытеснять готовность MVP.

## Требование к закрытию каждого item

В карточке задачи должны быть: проблема, acceptance criteria, точный scope,
зависимости, риски/неизвестное и метод проверки. Статус меняется на `DONE`
только после соответствующих тестов, API/error-path проверки и визуального
сценария для UI.
