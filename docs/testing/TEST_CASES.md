# Тест-кейсы

Ниже — два раздела. Первый (`TC-DIAG-*`) описывает диагностический инструмент «Doctor»
(read-only проверки окружения/контрактов/безопасности) и существовал до этого аудита. Второй
(`TC-AUTH/REQ/MSG/SUP/MAIL/AI/UI/DATA/TASK`) — продуктовые тест-кейсы, добавленные полным
аудитом 2026-09-17.

Формат каждого тест-кейса:

```text
Требование: — на какое требование ссылается (ID из requirements.yaml или инвариант)
Цель: — что именно проверяем
Предусловия: — что должно быть готово перед началом
Шаги: — что делать по порядку
Ожидаемый результат: — что должно произойти
Текущий результат: — что происходит на самом деле сейчас
Автоматизация: — каким инструментом это стоит автоматизировать
Статус: — PASS / FAIL / BLOCKED / NOT_TESTED (см. пояснение статусов ниже)
```

Статусы (системные значения, с пояснением):

| Статус | Значение |
|---|---|
| `PASS` | Проверка выполнена, результат совпал с ожидаемым |
| `FAIL` | Проверка выполнена, результат разошёлся с ожидаемым (проблема подтверждена) |
| `BLOCKED` | Проверку нельзя выполнить сейчас (например, функции не существует) |
| `NOT_TESTED` | Проверка ещё не проводилась — не путать с PASS |
