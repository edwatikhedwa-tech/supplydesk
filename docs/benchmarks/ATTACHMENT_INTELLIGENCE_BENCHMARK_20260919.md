# Attachment Intelligence — синтетический benchmark и pipeline v1 (EDW-33)

Всё синтетическое: реальная почта не читалась, наружу ничего не отправлялось. Ключ RouterAI читается из `.env`, в отчёты не попадает.

## Порядок (ground truth раньше pipeline)
1. Генератор + 60 файлов + `inputs.json` (всё, что видит pipeline) + `ground_truth.json` (sha256 файлов, источник каждого факта, must-not-extract, ожидаемая привязка к позициям, ожидаемое ручное ревью) — коммиты `360d673`, `540e724`. Перед первым прогоном исправлены 3 дефекта самих фикстур (заголовок «за 100 шт», неоднозначный alt у шайб, «аналог» в списке лишних позиций).
2. Pipeline: `mail/attachment_intelligence.py`; не импортирует ни каталог, ни истину. Runner читает только `inputs.json`; оценка — `score.py`.
3. **Правки после первого прогона (записаны в `ground_truth.json → corrections`):** (а) *benchmark-label correction*: `vat_mode` был «unspecified» из-за бага генератора, в документах «с НДС 20%»; (б) *fixture-layout*: заголовки колонок налезали друг на друга на странице (три подписи сокращены). Ожидаемые значения цен/SKU/позиций не менялись.

Состав: 12 текстовых PDF, 8 сканов-PDF, 19 XLSX (в т.ч. 330 строк, скрытая колонка, 2 листа, формулы, цена за 100 шт, USD), 9 DOCX, 8 JPG/PNG (поворот, размытие, низкий контраст, штамп, тень, скрин чата, малое разрешение), 4 битых/не-КП файла, 2 байтовые копии. 56 писем, 11 с несколькими вложениями. Запросы 5, 8, 12 и 30 позиций.

## Каскад
hash → парсер (XLSX-ячейки, DOCX-таблицы/абзацы, PDF-слова с координатами) → локальный OCR Windows.Media.Ocr (бесплатно) → таблица по словарю заголовков → **контрольная сумма qty×цена=сумма строки** (ремонт OCR-цифр и восстановление qty только при её выполнении) → vision-модель только для страниц, которые OCR не дочитал, ответ принимается лишь при контрольной сумме + видимой в OCR-строке цифре → иначе ручное ревью. Привязка к позициям детерминированная: exact / analog / ambiguous / unmatched.

Побочный вывод: cheap-текстовая модель по OCR-строкам ничего не дала (после исправления бага сравнения чисел: 1 факт восстановлен, и он неверен) — в финальной конфигурации выключена. Vision «reasoning»-модель `qwen3.7-flash` не годится (10–80 с, 0 принятых ответов); `gemma-3-12b` делала согласованные по сумме, но неверные строки → добавлена проверка «цена или сумма видна в OCR-строке».

## Классификация оставшихся ошибок
- OCR (9 строк): цифры не прочитаны ни OCR, ни vision (размытие/шум, длинная страница на 14 строк) — на ревью.
- validator: 14 лишних ревью (не ошибки данных: неоднозначные аналоги, нечитаемые строки).
- parser / prompt / model / candidate retrieval / position matching: 0 ошибок значения; retrieval-стадии нет (кандидаты — сами позиции запроса).
- Привязка «осторожно, а не неверно» (12 строк): 6205-2Z vs 6205ZZ (общий номер модели), «Смесь огнеупорная» vs «Раствор огнеупорный» (синонимы), OCR-искажённые артикулы.

## Мультивложения (11 писем)
Дубликат по hash считается один раз (m53); два формата одного КП подтверждают друг друга (m11, 5 позиций); расхождение цен → конфликт и ревью, оба значения сохранены (m12 2/2, m30 15/15, m55 6/6, m56 3/3, m46 2 из 5 — вторая часть в плохом фото); файл условий отдаёт срок доставки файлу КП (m02); файл без цен не создаёт фактов (m36); битый + рабочая копия — рабочее извлекается, письмо на ревью (m49). **Слабость набора:** m54 случайно без расхождения цен (EDW-37).
