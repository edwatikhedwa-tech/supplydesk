# Долг документации (Documentation Debt)

Найдено при полной русификации `docs/**`. Ничего из перечисленного не удалено и не
переписано по содержанию в этом проходе — только зафиксировано, как и было явно указано в
задаче. Решения о слиянии/удалении — за владельцем.

| Документ | Проблема | Актуальность | Возможное действие |
|---|---|---|---|
| `docs/CURRENT_STATE.md` (корень) | Описывает то же самое назначение, что `ai/CURRENT_STATE.md` и новый `docs/system/CURRENT_STATE.md` — три документа с похожим названием и пересекающейся ролью | `HISTORICAL`, заморожен 30.08.2026 — сам себя честно помечает как неактуальный | Оставить как историческую запись (уже корректно размечен); не путать с двумя другими при чтении |
| `docs/DECISIONS.md` (корень) | Аналогично: три места, где могут жить «решения» — этот файл, `ai/DECISIONS.md`, и записи в `docs/domain/SUPPLIER_MODEL.md` в виде `DECISION-022`/`DECISION-024` | `HISTORICAL`, сам ссылается на `ai/DECISIONS.md` как на текущий источник | Оставить как есть; уже корректно размечен и не противоречит остальным |
| `docs/architecture/COMPONENT_MAP.md` | Секция «Границы UI Frontend» описывает `frontend/` (старая версия) как единственный frontend — не упоминает `frontend-v2` вообще | Помечен `status: CURRENT`, но устарел по факту (написан 04.09.2026, до появления `frontend-v2`) | Дополнить или заменить ссылкой на `docs/frontend/FRONTEND_ARCHITECTURE.md`, который отражает реальное состояние |
| `docs/product/CAPABILITY_CATALOG.md` | `CAP-FRONTEND-001` описывает только `frontend/` и его тесты (`frontend/tests/`) — не знает о `frontend-v2` | `status: CURRENT`, тоже устарел по факту | Добавить отдельную строку `CAP-FRONTEND-002` для `frontend-v2` либо явно указать, что запись описывает retired-версию |
| `docs/testing/TEST_CATALOG.yaml` | `TEST-FRONTEND-001`/`002` указывают только на `frontend/tests/*.spec.ts` (Playwright для старой версии) — ни одной записи для `frontend-v2`, у которого браузерных тестов нет вообще | Актуален для того, что описывает, но создаёт впечатление, будто frontend вообще покрыт тестами | См. `docs/system/KNOWN_GAPS.md` `GAP-010` — добавить запись, честно фиксирующую отсутствие покрытия `frontend-v2`, когда оно появится |

| `docs/requirements/TRACEABILITY_MATRIX.csv` vs `docs/validation/TRACEABILITY_MATRIX.md` | Аналогично: два документа трассировки, CSV — на уровне capability/диагностики, MD — на уровне отдельного требования из нового аудита | Оба актуальны для своего охвата, не противоречат | Со временем можно объединить в один источник или явно связать перекрёстными ссылками |
| `docs/product/messages-workspace.md` | Сам документ уже помечен как описывающий старый frontend (`EmailWorkspace` из `frontend/`, не `frontend-v2`) | Помечен как замещённый (`SUPERSEDED`) корректно, но всё ещё числится в `docs/product/README.md` как «текущий сценарий» без пометки об этом в самом README | В `docs/product/README.md` рядом со ссылкой на этот файл стоит явно отметить, что он описывает retired-интерфейс |

## Не являются долгом (проверено отдельно, для полноты)

- `docs/domain/SUPPLIER_MODEL.md` и `docs/product/SUPPLIERS.md` (новый) не дублируют друг
  друга: первый — общая модель, второй — конкретно найденная в аудите проблема дублирования
  идентичности. Они явно ссылаются друг на друга.
- `docs/ui/MESSAGES_SCREEN_SPEC.md` и `docs/product/MESSAGES.md` (новый) также не дублируют:
  первый — детальная спецификация экрана, второй — сверка бизнес-правил по итогам аудита,
  явно ссылается на первый как на подтверждённый источник.
