# TASK-MESSAGES-PRIMARY-FILTER-20260831

## Цель

Изменить только пользовательское отображение на `/messages`: по умолчанию
показывать отправленные письма и переписки с ответами, а письма, которые ещё
не отправлены, показывать в отдельной очереди. Отправка, API, база данных,
статусы доставки, привязки к заявкам и фоновые процессы были вне scope.

## Подтверждённое состояние до изменения

- В checkout: ветка `codex/TASK-STATE-CONTROL-20260830`, base HEAD
  `1b3388b3e34bd6082aade6f5974cff3e5d788b52`.
- Локальный сервер: `http://127.0.0.1:8000/`.
- Read-only снимок API во время проверки:
  `/api/correspondence` — `80` записей; `/api/mail/queue/messages` — `64`
  записи.
- Из correspondence `77` записей соответствуют правилу «отправлено или есть
  ответ», а `3` записи без отправленного письма/ответа скрываются из основного
  списка. Queue-only записи уже отдавались отдельным endpoint очереди.

## Что изменено

### `frontend/src/components/mail/threadStatus.ts`

Добавлен `isPrimaryCorrespondence`. Он оставляет в основном списке тред, если:

- последнее исходящее письмо имеет статус `sent`; или
- у треда есть ответ (`replies_count > 0`); или
- последнее сообщение входящее (`last_message_direction === 'inbound'`).

Так переписка с полезной историей не исчезает из-за более позднего
транспортного статуса, а отправка, которая ещё не состоялась, не выглядит как
обычная история.

### `frontend/src/components/mail/ThreadList.tsx`

- Первичный фильтр включён по умолчанию и назван `Отправленные и ответы`.
- Счётчик первой кнопки считает только этот набор.
- `Ожидает ответа` считается внутри отправленных/отвеченных тредов.
- Пустое состояние объясняет отсутствие отправленных писем или ответов.
- Текст пустого состояния получил контраст, проходящий проверку доступности.

### `frontend/tests/frontend-audit.spec.ts`

- Добавлен сценарий, который проверяет отправленный тред, тред с ответом,
  queue-only, failed и delivery-unknown состояния.
- Обновлён сценарий delivery-unknown: запись не должна быть в основном
  списке, но прямое открытие из карточки поставщика по-прежнему показывает
  действия проверки и безопасного повтора.
