# Аудит и доработка страницы «Мои заявки»

> **HISTORICAL — NOT CURRENT.** Это датированный аудит интерфейса. Текущие
> возможности и ограничения проверяются в [`../../ai/CURRENT_STATE.md`](../../ai/CURRENT_STATE.md)
> и по коду/тестам.

Дата: 27 августа 2026 года<br>
Статус: рекомендации аудита реализованы в рамках согласованного объёма; дальнейшие продуктовые решения перечислены ниже.

## Цель

Проверить и улучшить экран `/requests` как рабочий список снабженца: быстро увидеть состояние заявки, найти нужную запись, понять ошибку и открыть заявку на следующем шаге. Аудит выполнен по документации проекта, `DESIGN.md` и правилам `frontend-product-engineer`.

## Что было подтверждено до изменений

- На desktop таблица была читаемой.
- На ширинах `1024px`, `768px` и `390px` таблица имела внутреннюю горизонтальную прокрутку шириной около `860px`; на мобильном экране без прокрутки были видны только название и статус.
- Ошибка `GET /api/requests` не имела `catch`: интерфейс завершал загрузку и показывал «Заявок пока нет», то есть ошибка выглядела как честное пустое состояние.
- Фильтр «Обновляется» отсутствовал, хотя такой статус есть в типах и данных.
- Поиск и сортировка жили только в локальном состоянии и не восстанавливались из URL.
- У таблицы отсутствовали `scope="col"`, у фильтров — `aria-pressed`, у поиска — явная доступная подпись, у сортировки — нативная семантика раскрывающегося списка.
- Обычная кнопка «Обновить» была на дашборде. По решению владельца продукта она не нужна: для обычного обновления используется `F5`.

## Что сделано

### 1. Адаптивный список

- На ширинах ниже `xl` (`1280px`) таблица заменяется карточками заявки.
- Карточка без горизонтального скролла показывает название, номер, дату, статус, дедлайн, число поставщиков и ответов, а также явное действие «Открыть».
- На широком desktop сохраняется таблица с плотной сеткой числовых колонок.
- Убрана кликабельность строки таблицы без клавиатурной семантики: в desktop главным интерактивным элементом стала явная ссылка на заявку.

### 2. Ошибка загрузки и восстановление

- Добавлен отдельный loading-state со скелетоном.
- Добавлен error-state «Не удалось загрузить заявки» с безопасным текстом и кнопкой «Повторить загрузку».
- Ошибка больше не превращается в список из нулевых заявок.
- Во время повторной попытки кнопка блокируется и показывает «Загружаем…».
- В строке/карточке заявки со статусом `error` теперь видна причина `last_error` и действие «Открыть», чтобы пользователь понимал следующий шаг.

### 3. Фильтры, поиск и сортировка

- Добавлен фильтр «Обновляется».
- `filter`, `q` и `sort` хранятся в URL. Состояние можно восстановить ссылкой, а F5 не сбрасывает рабочий контекст.
- Сортировка «По статусу» теперь поднимает сначала ошибки, затем обновляющиеся и ищущиеся заявки, затем черновики и завершённые записи. Это соответствует рабочему приоритету, а не алфавитному порядку кодов.
- Для пустого результата добавлена кнопка «Сбросить фильтры».

### 4. Доступность и визуальная система

- Добавлены доступные имена поиска и очистки поиска.
- Фильтры получили `aria-pressed` и группу с подписью.
- Сортировка переведена на нативный `select` с доступной подписью.
- Заголовки таблицы получили `scope="col"`.
- Для основных кнопок, ссылок и элементов управления добавлены видимые focus-состояния.
- Контент страницы использует `Procure Sans`, как предписано `DESIGN.md`; карточки, рабочая белая поверхность и cobalt-action остаются частью текущего языка SupplyDesk.

### 5. Обновление страницы

- Обычная кнопка «Обновить» удалена с дашборда.
- В штатном состоянии экран не предлагает отдельный manual refresh: пользователь обновляет страницу через `F5`.
- Кнопка «Повторить» сохранена только в error-state: это не дублирование F5, а восстановление после конкретного неудачного запроса.

## Изменённые файлы

- `frontend/src/pages/RequestsList.tsx` — адаптивные карточки, состояния, URL-фильтры, доступность и error details.
- `frontend/src/pages/Dashboard.tsx` — удалена обычная кнопка «Обновить», retry оставлен только в ошибках.
- `dashboard-recommendations.md` — уточнено решение по F5 и retry.
- `PROJECT_DOCUMENTATION.md` — добавлена запись о фактической проверке.

## Что не менялось

- Backend API `/api/requests` и схема данных не менялись.
- Логика поиска поставщиков, отправки почты и карточки заявки не менялась.
- Кнопка «Новая заявка» и переходы в существующие разделы сохранены.
- Другие грязные изменения рабочей копии не откатывались и не редактировались в рамках этой задачи.

## Рекомендации следующего этапа

1. **P1 — добавить серверную пагинацию**, когда список заявок перестанет помещаться в один ответ: сейчас адаптивная выдача решает визуальную проблему, но не объём данных.
2. **P1 — определить единый контракт «Требует внимания»**: текущий KPI считает ошибки заявок и ведёт в `filter=error`; если туда добавятся ошибки почты, зависшие поиски или дедлайны, нужен отдельный список причин и совпадающая фильтрация.
3. **P2 — вынести повтор поиска в карточку заявки**, а не в список: запуск поиска — изменяющее действие, поэтому перед ним нужен понятный контекст и подтверждение.
4. **P2 — добавить автотесты frontend-сценариев**: успешная загрузка, HTTP/API ошибка, retry, фильтры, URL-состояние, карточка на mobile и keyboard focus.
5. **P2 — завершить унификацию навигационного rail**: `/requests` уже использует Procure Sans, но graphite-rail пока реализован не как единая политика для всех рабочих экранов. Перед общей перекраской нужно проверить остальные разделы, чтобы не получить частичную визуальную миграцию.
6. **P3 — добавить обновление по событию или по входу на экран**, если заявки начнут меняться в фоне. Пока сознательно выбран простой контракт: загрузка при открытии и обновление через `F5`.

## Definition of Done для этой итерации

- На `390px`, `768px` и `1024px` ключевые поля заявки видны без горизонтального скролла.
- Ошибка API отображает error-state, а не пустой список; retry выполняет повторный запрос.
- Фильтр «Обновляется» доступен.
- Фильтр, поиск и сортировка восстанавливаются из URL.
- Ошибка заявки показывает причину и ведёт к заявке.
- Таблица и контроли имеют базовую семантику и видимый focus.
- Обычная кнопка «Обновить» удалена; «Повторить» остаётся только для error-state.

## Дополнение 27 августа 2026 — повторная визуальная диагностика строки ошибки

По скриншотам исправлен дефект, при котором сообщение `Нужна проверка`
сжималось в ячейке названия и не использовало свободную ширину строки.

- на desktop сообщение теперь находится в отдельной строке сразу под ошибочной
  заявкой, занимает всю ширину таблицы через `colSpan=7` и выравнивается по
  центру;
- у сообщения есть `role="alert"`, поэтому ошибка доступна assistive tech;
- последний столбец «Ответов» имеет выделенную ширину, центрирование и
  внутренний правый отступ, поэтому цифра не прилипает к краю;
- на ширинах ниже `xl` продолжает работать карточный режим, где сообщение об
  ошибке остаётся частью карточки заявки;
- авторизованный рендер повторно проверен на `1440px` и `390px`: таблица/карточка
  не выходят за viewport, ошибка присутствует, последний столбец читаем.
