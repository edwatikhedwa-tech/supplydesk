# SupplyDesk frontend QA

> **HISTORICAL / PROCEDURE REFERENCE.** Команды и результаты в этом файле
> относятся к датированным проверкам и не заменяют текущий state. Актуальные
> ограничения и последняя приёмка находятся в
> [`../../ai/CURRENT_STATE.md`](../../ai/CURRENT_STATE.md) и отчётах под
> [`../../ai/reports/`](../../ai/reports/).

Этот документ описывает локальный набор проверок интерфейса. Он предназначен для повторяемого аудита страниц, состояний компонентов и содержимого входящих писем.

## Установленный набор

- Playwright `1.62.1` — реальные сценарии, клики, viewport-проверки и скриншоты.
- `toHaveScreenshot()` — pixel-level baseline-сравнение в Storybook-тестах.
- `@axe-core/playwright` `4.13.0` — accessibility-проверки DOM, landmark-структуры, labels, ARIA и контраста.
- Lighthouse `13.4.1` и Lighthouse CI `0.15.1` — performance, accessibility и best practices.
- Storybook `8.6.15` с `addon-a11y`, `addon-essentials` и `addon-interactions` — изолированная проверка компонентов и состояний.
- CSS/DOM assertions — проверка `scrollWidth`, выхода элементов за viewport, размеров интерактивных элементов и ширины/overflow содержимого iframe письма.

Зависимости установлены локально в `frontend/node_modules`; глобальные пакеты не требуются.

## Команды

Запускать из `frontend`:

```powershell
npm run typecheck
npm run build
npm run test:visual
npm run test:storybook-visual
npm run build-storybook
npm run lhci
```

Универсальная геометрическая проверка страниц:

```powershell
node C:\Users\edwat\.agents\skills\frontend-product-engineer\scripts\browser_geometry_audit.mjs `
  --url http://127.0.0.1:8000/login `
  --out C:\Users\edwat\OneDrive\Документы\ChatGPT\SaaS\frontend\artifacts\frontend-audit-login
```

Скрипт проверяет несколько desktop/tablet/mobile viewport, общий горизонтальный overflow, элементы за границами viewport, интерактивные размеры и сохраняет PNG/JSON-артефакты. Для защищённых маршрутов используется уже авторизованная вкладка in-app browser: cookies, localStorage и токены не извлекаются и не сохраняются.

Для обновления visual baseline нужна явная команда после визуального review:

```powershell
npm run test:storybook-visual -- --update-snapshots
```

Нельзя принимать baseline автоматически: сначала нужно просмотреть diff.

## Проверки писем

Для каждого доступного письма проверяются:

- текстовая длина и наличие реально отображаемого текста;
- отсутствие горизонтального overflow внутри email iframe;
- доступность ссылки открытия письма в переписке;
- наличие/отсутствие изображений и корректное поведение remote-image blocker;
- раскрытие/сворачивание карточки;
- сохранение unread-состояния для письма без заявки;
- desktop и mobile rendering с длинными subject/body, ссылками и marketing HTML.

Содержимое писем и внешние tracking URL не включаются в отчёты и git.

## Ограничения и риски

- `npm run lhci` собрал JSON-результат, но завершился с exit `1` на Windows из-за `EPERM` при удалении временного Chrome-профиля после запуска. Это инфраструктурный cleanup-сбой, а не доказательство успешного quality gate.
- Playwright public test намеренно не отключает axe-нарушения через exclude. Декоративный canvas авторизации помечен `aria-hidden`, поэтому текущий login axe-check проходит.

`*-delivery-unknown-thread.png`; при первом прогоне исправлены выбор видимого
mobile/desktop status badge, контраст вкладок и служебного текста переписки,
а также accessible name кнопки возврата. Реальный authenticated production
mail flow и фактическая внешняя отправка в этом browser-прогоне не выполнялись:
API-ответы сценария замокированы тестом.

Текущий lint: exit `0`, 13 предупреждений без ошибок; typecheck и build: exit
`0`. Подробные backend/frontend ограничения находятся в
`EMAIL_INTEGRITY_ITERATION1_REPORT.md`.

В corrective pass Composer для массовой отправки создаёт idempotency key один
раз на draft-intent и сохраняет его для повторного HTTP-запроса после сетевой
ошибки; после успешного завершения следующая отправка получает новый ключ.
